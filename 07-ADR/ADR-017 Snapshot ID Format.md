# ADR-017 — Snapshot ID Format

Status: Accepted
Ngày: 2026-07-22
Liên quan: [[Discovery — Snapshot Metadata Ownership]], [[CHECKPOINT-2026-07-22]]

---

## Context

`Snapshot ID` là 1 trong 4 field thuộc nhóm Snapshot Metadata trong header `TRANSACTION_STAGING` (xem [[Discovery — Snapshot Metadata Ownership]]). Trước đây có 2 hướng từng bàn: Timestamp-based hoặc Sequence Counter (`SNAP-YYMMDD-NNN`, cần Apps Script counter đọc/ghi theo ngày). Cả hai đều cần thêm cơ chế sinh số (Counter/LockService).

## Decision

```
Principle: 1 Event = 1 Snapshot = 1 Immutable Transaction Truth
Format: SNP-{EventID}  (ví dụ: DN-ASSM-260612-001 → SNP-DN-ASSM-260612-001)

Rule 01 — Generate Once: chỉ tạo 1 lần lúc Generate Snapshot
Rule 02 — Immutable: không đổi sau Approval/Reject/Rollback/Execution State change
Rule 03 — One-to-One: 1 Event ↔ 1 Snapshot
Rule 04 — Reference Key: khóa liên kết TRANSACTION_STAGING/INVENTORY_LEDGER/STOCK_POSITION/ERROR_LOG/AUDIT
Rule 05 — Human Readable: không dùng UUID ngẫu nhiên
```

Mượn tính duy nhất trực tiếp từ Event ID thay vì sinh số riêng — không cần Counter/LockService.

**Future Boundary:** Snapshot Versioning (1 Event → nhiều Snapshot V1/V2/V3) là Mission riêng, chỉ mở khi Reality thật sự cần — không thiết kế trước.

## Consequence

- Chỉ giải quyết field `Snapshot ID` trong 4 field của Snapshot Metadata. 3 field còn lại (`Compiler Source`, `Generated By`, `Generated Time`) vẫn Open — Proposal cũ (Engine owns, Apps Script) chưa Freeze cho các field này.
- **Phụ thuộc chưa giải quyết:** tính duy nhất của `SNP-{EventID}` phụ thuộc hoàn toàn vào Event ID đã unique. Theo bằng chứng hiện có, Event ID đang nhập tay (`Generated By` = người thật) — rủi ro trùng Event ID (2 người cùng ngày) vẫn tồn tại ở tầng tạo Event ID, không phải rủi ro mới sinh ra từ Freeze này. Không chặn Freeze này vì rủi ro nằm ngoài phạm vi field `Snapshot ID`.
- Giảm phạm vi câu hỏi mở ở [[Discovery — Boundary Formula vs Engine]] — bớt 1 lý do cần Apps Script Counter riêng cho Snapshot ID.
